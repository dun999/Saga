Open Saga

Privacy & cookies

Last updated: 30 September 2026

In short: Saga uses only the cookies it needs to sign you in, confirm your own requests, and unlock your vault — no analytics, no ads, no tracking. Your memory is stored encrypted on Walrus. Accounts you connect are encrypted with a key derived from your wallet that Saga never stores, and Disconnect deletes them. A username is guest mode: anyone who types the same name sees its memory.

Wallet or guest

  • Wallet. Your Sui address is your identity, proven by a signature, so your memory is yours alone. Only wallet users can connect accounts (Claude, ChatGPT, Grok, GitHub, API keys).
  • Guest username. Quick to try, but it proves nothing: anyone who enters the same username sees and adds to that username's memory, chats and files. Guests can't connect accounts. Don't put anything private in a guest session.

Who runs this

Saga is open-source software built for the Walrus “Chatbots That Remember” hackathon. Each deployment is run by its operator — whoever hosts the server you are using. This page describes how the software handles data; the operator is responsible for the server it runs on.

Your connected accounts

  • Encrypted at rest. Tokens, API keys and provider sign-ins are sealed with your vault key. Beside the ciphertext the server keeps, in the clear, only a short fingerprint of your vault key (to tell whether your browser holds the right one) and whether a Claude credential is a token or an API key. The last characters of a key and your GitHub username are sealed too; the app shows them only after it opens them with your key.
  • No leftovers from the tools. Claude Code, Codex and Grok write their own files while they work, including session transcripts with your prompts and memories. When your last call ends, Saga deletes all of them and keeps only your sealed sign-ins, plus the plan-usage numbers it shows you.
  • Unlocked only for your requests. While one of your agents runs, Saga decrypts what it needs for that run, inside a sandbox that no other user's agents can see, then seals it again. During that window the server necessarily holds the plaintext in memory — so you are trusting the operator of this deployment while your agents run.
  • Disconnect deletes. Disconnecting an agent removes its stored token, key or sign-in from the server. Signing out clears your session and vault cookies.
  • Unless the operator runs the agents. A deployment can instead run every agent on the operator's own provider logins. Then there's nothing for you to connect, your prompts go through the operator's accounts, and agents run without a per-user sandbox, so use such a deployment only if you trust its operator.
  • Use a capped key if you prefer. An API key with a monthly spending limit bounds what any key can cost.
  • Some wallets can't recreate the key. Wallets that sign with rotating keys (for example Google sign-in wallets) may produce a different vault key on a new device. Saga can't open what was sealed before, and asks you to reconnect.

Third parties

Using Saga involves these services, each under its own terms and privacy policy:

  • Walrus Memory (MemWal) relayer and Walrus mainnet — stores and recalls your encrypted memory.
  • Sui mainnet (GraphQL) — verifies wallet signatures that aren't checked locally.
  • Boundless inference — runs the built-in @saga agent, so it receives the prompts sent to it, including relevant memories, on the operator's account.
  • The AI providers you connect — Anthropic (Claude), OpenAI (Codex / ChatGPT), xAI (Grok) and any API you add receive the prompts your agents send, including relevant memories, under your own account.
  • GitHub — only if you connect it: sign-in, and the repos you pick are cloned from and pushed to it.
  • esm.sh — serves the open-source Wallet Standard library the sign-in page uses to find your wallet.
  • Google Fonts — Saga's pages load their typefaces from Google.

Deleting your data

  • Connected accounts: Agents → Disconnect deletes them from the server.
  • Session and vault key: Profile → Sign out, or clear this site's cookies.
  • Memory on Walrus: memories are stored as blobs on a decentralised network. Ask the operator to forget your namespaces in the relayer's index; blobs themselves expire with their Walrus storage period.
